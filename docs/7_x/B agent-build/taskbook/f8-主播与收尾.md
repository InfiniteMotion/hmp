## 1. 阶段定位

**电台从"能选歌"走到"会编排"。**

`4bf5765` 把 RadioAgent 从 M6 的功能实现推进为**有编排记忆的静默 DJ**（决策内核 + 播放观测治理 + Hello 卡扩展），`f3a4f6a` 收尾 W 阶段呈现层并重设计电台卡。两笔都是"最后一公里"性质——**功能已在，缺的是让它真能听清用户、并把编排思路传达出来**。间隔一周，改同一层（呈现与电台交互），合并为一族。

> ⚠️ **口径修正（2026-09-15，以代码为准）**：本族曾被称为"电台主播化 / 有人格 / 可持续对话主播"。
> 核对 `4bf5765` 真实代码后确认该表述**不成立**：电台**不与用户对话、不生成面向用户的文案**。
> 定稿口径见 [`../design/agent-radio.md`](../design/agent-radio.md) §0 与 C1——
> 电台的动作只有 `NONE` / `APPEND` / `REPLACE` 三种，触发只有 `SETTLED` / `QUEUE_LOW` 两种，
> 判断阶段**不暴露任何工具**（C5）。所谓"主播"，指的是**编排者的连续性**（一段对话贯到底 + 节目档案 ledger + 按语），
> 不是"会和用户聊天的角色"。此处的"人格"仅指 `CompanionProfile.DJ` 的节目模式（约束工具使用风格），不产生文案。

## 3. 引擎 → UI 映射总表

| 引擎产出（已存在） | 消费 UI（本阶段做） |
|-------------------|-------------------|
| `PresenceBus.badgeState`（CompanionBadge） | 底栏伙伴胶囊徽标（未读红点 / 待确认脉冲 / 电台运行小绿点） |
| `PresenceEvent.NoticeAvailable`（`MasterAgent.handleDjBlank` emit） | AgentNoticeBar 侧条（带撤销） |
| `PresenceEvent.SkipDetected`（`MasterAgent` skip listener emit） | AgentNoticeBar 侧条 "跳过了《XX》，正在换一批…" |
| `PresenceEvent.DjBlank`（trackChange emit） | 门面问候区触发 `generateDjSegue()` 或 fallback |
| `PresenceEvent.TaskProgress`（`ReActLoop.run` emit） | 对话页三点脉动 |
| `PresenceEvent.AgentProgress`（Enrich emit） | 胶囊徽标脉冲 + 门面"富化进行中"提示 |
| `PresenceEvent.CloudQuotaExhausted`（`GlobalTokenCounter`） | AgentNoticeBar "云端额度耗尽，已切换本地模式" |

**接线现状**（`AppRoot.kt` `LaunchedEffect` 消费的事件）：

```
PresenceEvent.NoticeAvailable     → ✅ 已接 AgentNoticeBar（但 showUndo=false 硬编码）
PresenceEvent.SkipDetected        → ✅ 已接 AgentNoticeBar（同上）
PresenceEvent.DjBlank             → ❌ 未接（门面问候区没写）
PresenceEvent.CompanionBadge      → ❌ 未接（胶囊徽标状态没渲染）
PresenceEvent.TaskProgress        → ❌ 未接（对话页三点脉动没写）
PresenceEvent.AgentProgress       → ❌ 未接（后台状态胶囊徽标没反映）
PresenceEvent.CloudQuotaExhausted → ❌ 未接（本地兜底无 UI 提示）
```

**骨架组件现状**（已存在但接线不完整）：


## 6. 严格不做什么

- ❌ 不做新路由——全部嫁接既有六面（门面 / 对话 / 浮层 / 侧条 / 设置 / 审计）
- ❌ 不做语音（F9 独立 gate）
- ❌ 不做报告叙事（F9-T1）
- ❌ 不做 `agent_memory` DAO 持久化（T 阶段明确留后续）
- ❌ 不做跨会话历史恢复（F9-T2 会话持久已覆盖）
- ❌ 播放中不弹伙伴浮面——**唯一硬纪律：用户手势进行中永远闭嘴**

## 8. 经验与踩坑

- **"接线只做一半"是最容易被忽略的债务**：`CompanionCapsule`（114 行）、`AgentQuickSheet`（126 行）、`AgentNoticeBar`（91 行）三个组件都写得很完整，但 `AppRoot` 只传了 `onClick`、`showUndo=false` 硬编码、C 键没监听。**组件完成度 ≠ 功能可用度**，接线清单要单独维护。
- **引擎发了事件没人消费，静默失败**：`PresenceBus` 七个事件里四个 ❌ 未接。这类问题的表现是"功能做了但用户没感觉"，排查成本极高——因为代码路径全对。**做法：每个事件必须登记消费点，未接的显式标 ❌。**
- **重构中途积累未提交 diff 是风险**：W 阶段多处改动在未提交 diff 中积累，`G8`/`G15` 此前编译被中断未验。提交前统一跑兜底编译是必要纪律。
- **硬纪律要写进验收**：「播放中不弹伙伴浮面」是唯一一条不可协商的交互纪律，因此它出现在验收表里而不是设计说明里——**能被验收的纪律才守得住**。
