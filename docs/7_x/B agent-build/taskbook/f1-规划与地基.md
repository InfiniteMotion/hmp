## 2. 设计侧交付

`agent.md` 确立的内容（后续所有阶段的依据）：

| 项 | 内容 |
|----|------|
| 定位 | 以播放器为身体的音乐伙伴；**存在反馈闭环才叫伙伴**（用户行为改变下次决策） |
| 产品红线 | ① 伙伴只属于你（记忆只存设备，无账号无云同步）② 隐私明示（对话携带曲库摘要发往用户自填端点） |
| 概念体系 | 工具 / 模型调用 / 任务 / 触发器 / 策略 / 记忆 / 人格（七概念） |
| 双层机制 | 本地是响应保障，云端是决策权威；三轮协作 + 四条执行纪律（响应保障/留痕可撤销/双向回流/降级兜底） |
| 上下文组装 | 记忆 ≠ 上下文；曲库概况两级打包（清单法 / 概览法） |
| 认识论 | 三层可信度 T0 行为 > T1 手工 > T2 模型；静态信任链仅在同类证据冲突时生效，异质证据走融合仲裁 |
| 实施序列 | B0–B6（B4 在 B5 前——确认交互是电台「隐式接受」的校准基准） |
| 铁律 | 零新增第三方依赖；`:shared` 不反向依赖 shared-ui |

## 5. 经验与踩坑

- **备份快照漏了溯源字段**（review 修复 2026-08-28）：v1 快照还原会让用户修正退化为可被模型覆盖。修复方式：**备份快照 v2 携带标签溯源字段**（`MusicLabelSnapshot` + source/confidence/created_at/updated_at，可空默认 → v1 存量 JSON 兼容）——还原后 `source=USER` 保留规则①保护。
- **审计留痕顺序**：改为「主数据先落库、审计后写」。
- 移除 UNKNOWN println 残留。
- **双文档分工是伪命题**：方案与交互设计强行切两份，实际每次改动都要同步两处。合并为单一事实来源后，后续所有阶段都直接引用 `agent.md`，无一例外。
