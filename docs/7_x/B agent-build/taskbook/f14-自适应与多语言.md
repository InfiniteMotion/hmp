# F14 · Agent 界面自适应与多语言（横切加固）

> **定位**：方向 B（agent-build）收尾后的**横切加固章**。F1–F13 建完了能力与结构，
> 本章解决"agent 界面的**交付质量**"两件事：**看得舒服**（自适应显示适配）与**看得懂**（字符串资源收拢 + 14 语言）。
> **性质**：横切加固。不改任何交互逻辑与信息架构，只调布局形态与资源组织。
> **依赖**：F13（页面清单在其结构收敛后固定；`AgentVisuals` 等共享件已就位）。
> **用户裁定**（2026-09-21）：**先做 T1 UI 适配，再做 T2 字符串收拢**；多语言**本轮 14 语言全量交付**；自适应范围为**全部 agent 页面**。
> **范围扩展**（2026-09-21 二次裁定）：基建排查发现另一批"设施已建、agent 绕行"的同构欠账，用户裁定四项并入本章 → **T3 组件基建对齐**（①表单基础件 ②空态/状态件 ③尺寸令牌 ④状态色散点）；⑤ AgentNoticeBar 经调查为**死组件**（挂载但事件源零实装），**不并入**——补活属功能工作，调查结论见 §3.3。

***

## 0. 为什么立

两个问题都是 F13 收尾盘点（`taskbook/README.md` 已知验收缺口）里挂账的：

1. **自适应欠账**：agent 页面全部诞生于"手机竖屏优先"的开发节奏，
   布局按单档宽度写死。而项目早有窗口分级基础设施
   `common/layout/WindowSizeClass.kt`（Material3 三档断点 + 全局 `LocalWindowSizeInfo`），
   电台控制台（`RadioConsole`）也已自适配 —— **但 agent 的其余页面 0 消费**：
   - 桌面端宽窗（Expanded ≥840dp）下，对话页 / 看板 / 设置表单**拉满全宽**，
     可读性差（行长过长是排版大忌）；
   - 看板六卡固定"每行两个"，宽窗下右侧大量留白。
2. **本地化欠账**：agent UI 约十几批页面把界面文字**硬编码在 Kotlin 里**。
   实测（2026-09-21）：`ui/agent` 子树 **344 处**中文文案字面量（全 ui 树 426 处，agent 占八成）；
   而项目 14 语言资源设施齐全（`composeResources/values*` × 14，各 474 键，`stringResource` 用法成熟）。
   硬编码 ⇒ 非 zh 系统语言下 agent 界面**整页中文**，14 语言设施对 agent 形同虚设。

**本章产出不是新能力，而是"agent 界面在任意窗口尺寸、任意系统语言下都达到既有页面的交付水准"。**

***

## 1. 判据（三条，勿混）

1. **自适应 = 消费既有分级，不发明新断点。**
   只用 `WindowSizeClass.kt` 的三档（Compact <600 / Medium 600–840 / Expanded ≥840 宽；
   高 Compact <480 / Medium 480–900 / Expanded ≥900）与 `isLandscape` 等既有派生量。
2. **收拢 = 只收 UI 面向文案。**
   判据：**这段文字最终渲染给用户看的吗？** 是 → 进 `strings.xml`；
   发给 LLM 的消息、领域层回退文案、日志/调试文本 → **保留原样**（翻译它们反而污染模型输入）。
3. **翻译 = 14 语言全量交付。**
   每个新键在 14 个 `strings.xml` 中同时存在；占位符（`%1$s` 等）在各语言中**一个不少**。

## 3. 阶段

| 阶段 | 内容 | 产出 | 状态 |
|---|---|---|---|
| **T1** | **agent 页面自适应显示适配**（用户裁定先行） | 各 agent 页面消费 `LocalWindowSizeInfo`：对话页限宽、看板分栏、表单限宽居中、通知条/审计页适配 | 🟡 进行中 |
| **T3** | **组件基建对齐**（用户裁定并入；执行序：T1 → T3 → T2） | 表单页原生 `TextField`/`Button` 替换为基础件；空态统一 `DefaultEmpty`；agent 页 spacing 换 `LocalHMPDimens`；`Severity.Warn` 色收进 `AgentStatusColors` | ⬜ 待开工 |

> **执行序说明**：T3 排在 T2 之前 —— 组件替换会触碰 T2 要收拢的文案宿主，先定组件骨架再收文案，避免同一批字面量二次迁移。（用户原裁定"T1 先于 T2"不受影响，T3 插入其间。）

### 3.1 T1 设计：各页面适配形态（断点行为表）

| 页面 | Compact（手机竖屏，现状基线） | Medium / Expanded（横屏 / 平板 / 桌面） |
|---|---|---|
| 对话页 `ChatScreen` | 全宽（现状） | **内容限宽居中**（对话可读宽度上限 ~640dp），气泡宽度仍随容器 |
| Agent 看板 `AgentMonitorScreen` | 每行两卡 × 3 行（现状） | Expanded：**三列两行**（六卡一次尽收），Medium 保持两列 |
| AI 设置 `AIScreen` | 全宽（现状） | **表单限宽居中**（~600dp），分区结构不变 |
| Agent 配置 `AgentConfigScreen` | 全宽（现状） | **表单限宽居中**（~600dp）；宽行（如 Prompt 编辑）可放宽至 720dp |
| 审计页 `AuditLogScreen` | 全宽（现状） | 列表限宽居中（~640dp） |
| 通知条 `AgentNoticeBar` | 全宽横条（现状） | 保持全宽（通知条语义即横贯），内部文字限宽 |
| Hello 卡片区 | 现状轮播 | 卡片内容已按固定卡宽设计，随容器自适应，**仅回归验证** |
| 电台控制台 `RadioConsole` | 已自适配（BoxWithConstraints） | **仅回归验证**，不动 |

> 限宽统一走 `widthIn(max = …)` + 水平居中，不引入新布局文件；分栏用既有 `Row`/权重，
> **不引入 LazyGrid 之外的依赖**。

### 3.2 T2 设计：键命名空间与甄别原则

- **键命名空间**按页面/件分组（沿用既有风格）：
  `agent_monitor_*` · `agent_config_*` · `ai_settings_*` · `chat_*` · `companion_*` ·
  `radio_console_*` · `hello_card_*` · `audit_log_*` · `agent_notice_*`。
- **占位符**：动态拼接（歌曲名 / 数字 / 时段）一律改位置参数 `%1$s` / `%1$d`，
  禁止字符串拼接（语序在翻译里会变）。
- **甄别原则**见 §1 判据 2；`ChatAgentGateway` / `ChatViewModel` / `ControllerAgentPorts`
  中发给模型的文本**逐条保留**，并在代码注释标注「LLM 面向，勿本地化」。
- **默认语言（`values/`）= 英文**：新键以英文为默认值、`values-zh` 给中文，
  其余 12 语言全量翻译（用户裁定本轮交付）。
- **校验**：提交前脚本核对 **14 个文件键集合一致**（缺键 = 回落默认语言，静默劣化，不允许）。

### 3.3 T3 设计：组件基建对齐（四项）+ AgentNoticeBar 调查结论

**T3 四项改法**（对齐 §2.3 编号）：

| # | 改法 | 范围 |
|---|---|---|
| ① | `TextField`/`OutlinedTextField` → `HMPTextField`；`Button` → `MyButton`。**替换前提**：先核对基础件能力覆盖（密码变换/键盘选项/下拉锚等 AIScreen 用到的高级形态），缺能力先补基础件再替换，**不为对齐降级功能** | `AIScreen` 9 处 + `AgentConfigScreen` 7 处 |
| ② | `AuditLogScreen` 手写 `EmptyState` 删除，改 `DefaultEmpty`（emoji 装饰不做进基础件——若需副标题形态，扩展 `DefaultEmpty` 支持可选 `detail` 参数，agent 与既有页面共用） | `AuditLogScreen` |
| ③ | 魔数 spacing 换 `LocalHMPDimens` 令牌。**尺度**：只换"语义明确的间距"（页边距/卡片间距/分区间距 → `dimens.spacing.*`），图标尺寸、圆角、控件定宽等**非间距魔数保留**——令牌化不追求一行不漏 | 六页 + `HelloCard*` 按触碰面顺带 |
| ④ | `AgentMonitorScreen:362` 的 `Color(0xFFB26A00)` 收进 `AgentStatusColors`（新增 `Warn`），调用点改引令牌 | 1 行 + 令牌 1 行 |

**AgentNoticeBar 调查结论（2026-09-21，不并入 T3）**：三层核实——① 组件已挂载（`AppRoot.kt:554`，底栏上方随底栏显隐）；② 渲染接线完成（`AppRoot.kt:251–269` 订阅 `PresenceBus` → `currentNotice`），但**不传 `onUndo`**、唯一事件 `showUndo=false`，「撤销」按钮与"4s 撤销窗口过期转审计页"注释从未兑现；③ **事件源零实装**——`SkipDetected` 全仓无生产 emit 点，M6-T2 设计链 `skipEvents → MasterAgent 连跳≥2 → emit` 只修了前半（`ControllerAgentPorts.skipEvents` 有实现），MasterAgent 侧监听→emit 从未接（`MasterAgent.kt:1115` 注释自认"等观测面落地后再接"）。**判定：死组件（挂载但永不显示）**。补活属功能工作（观测面设计 + 事件接线 + 撤销链路），不属横切加固，**留待单独决断（补活 or 删除）**；即使补活，`skipEvents` 只覆盖经端口命令（对话/工具），播放页直连/通知栏/耳机路径天然不在内（`agent-radio.md` §7 已记录）。

## 5. 严格不做什么（本阶段内不擅动）

- **不改交互逻辑与信息架构**：不加/删功能、不调整操作流；只动布局形态与资源组织
- **不新建窗口适配机制**：不引入 `material3-window-size-class` 等新依赖，只用 `WindowSizeClass.kt`
- **不翻译非 UI 文案**：LLM 提示、领域回退、日志保持中文原文（它们不是界面）
- **不动 agent 链路之外的既有页面**（`HomeScreen` / `SearchScreen` 等的存量文案不在本章范围）
- **不做运行时语言切换**：跟随系统语言（既有行为），不在设置页加语言选择器
- **不做 AgentNoticeBar 补活/删除**：死组件（§3.3 调查结论），补活属功能工作，留待单独决断；T3 也不给它换基础件/令牌（避免给将死组件投资）
- **不为对齐降级功能**：T3 基础件替换前先核对高级形态能力（密码框/键盘选项/下拉锚），基础件缺能力先补基础件
