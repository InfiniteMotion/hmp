# 电台控制台（Radio Console）

> **本文件**：长按底栏伙伴胶囊唤起的**电台全屏面板**的唯一设计依据。
> **回答什么**：电台怎么关、关了意味着什么、这一档节目怎么被看见。
> **上游**：`agent-radio.md`（电台契约 C1–C5、存在面）｜`agent.md` §5.2（锚点与手势）｜`agent.md` 场景表
> **状态**：**v1 已实施（2026-09-19）** —— 三端编译通过（`:shared-ui:compileKotlinDesktop` / `:android:app:compileDebugKotlin`）。实施偏差见 §10。
> **替代**：`CompanionCapsule` 的「电台态长按 = 直接停止电台」（2026-09-19 临时实现，已被本面板替换）

***

## 0. 结论先行

**长按胶囊不再直接关闭电台，而是拉起一个全屏面板 ——「电台控制台」。关闭动作移进面板，且关闭不叫「停止」，叫「结束这一档」。**

一句话理由：**关闭是终态动作，不该由一个长按直接完成；用户需要先看清"我要关掉的是什么"。**
而一旦要给他看，就该把这一档节目**最值得看的东西**一并给他 —— 主播为这段收听排的节目单、每首歌的按语。

于是面板有两个职责，缺一不可：

| 职责 | 内容 | 为什么是它 |
|---|---|---|
| **看见** | 这一档的主题 / 在播 / **节目单（每首带按语）** / 主播思路 | 电台是"静默 DJ"：它不说话、只编排。**看不见编排，"电台在工作"就永远只是传言** |
| **收档** | 「结束这一档」+ 收束语（听了什么、切了什么） | 关闭从"破坏性按钮"变成**有始有终的收尾**；且有足够门槛防误触 |

> 门面是伙伴的脸，**控制台是这一档节目的脸**。

***

## 1. 为什么不是"给长按加个确认弹窗"

用户反馈是「关闭不应该是简单的长按，需要更复杂的交互」。实现这条有两条路，必须选对：

| 方案 | 做法 | 判断 |
|---|---|---|
| (a) 长按 → 确认弹窗「确认停止电台？」→ 确认 | 两层，但用户**仍然不知道自己关的是什么**；"复杂"只体现在多了一次点击 | ❌ 廉价的重 |
| (b) 长按 → **这一档的全貌** → 在看清之后收档 | 复杂度落在"信息"而不是"点击次数"上；顺带交付了电台最有差异化的东西 | ✅ **本方案** |

另有一条项目内原则必须遵守：`agent.md` 场景 5 明写「**过度确认违反许可无感**」（刚明说的可逆动作不再确认）。
所以本方案**不引入系统级强确认弹窗**，也不与既有 STRONG_CONFIRM 体系（删歌单/改 ID3）混淆 —— 停止电台**不是**那一档的危险动作（见 §5）。

## 2. 手势与状态机

```
胶囊常态（radioActive = false）            胶囊电台态（radioActive = true）  ← radiowaves 高亮
├ 点按 → 回门面                            ├ 点按 → 回门面（导航锚点不夺）
└ 长按 → 直接进对话页                        └ 长按 → 拉起「电台控制台」
      （轻量浮层已于 2026-09-19 移除）

电台控制台（全屏，自下而上浮现）
├ 下滑（见 §4 手势分工）→ 收起，电台继续跑
├ 点 ⋁ / 系统返回      → 收起，电台继续跑
└ 「结束这一档」        → 见 §5 → stopRadio() → 面板转「已收档」态 → 淡出
```

**要点**：
- **长按是门槛，不是动作**。长按 600ms 本身已是防误触手势（项目既有语义：`HapticEffect.LONG_PRESS`）。
- **面板打开期间电台照常运行**：观测、决策、续歌一律不停 —— 面板是**只读的观察窗**，不是"暂停收音"。
- **点按语义不变**（回门面）。它是"找伙伴=看左下角"的主锚点，不能因电台而被夺走。
- 电台在面板打开期间被**外部**停止（对话说停电台 / Agent 看板停止）→ 面板就地转「已收档」态，不硬消失。

## 3. 面板结构

全屏、自下而上浮现；沿用底栏胶囊的 **haze 质感**（半透明模糊底），内容为单列滚动。

```
┌─────────────────────────────────────────┐
│  ▁▁▁                        （抓手条）      │  ① 抓手 + 收起
├─────────────────────────────────────────┤
│  ((•))  自动电台                    ⋁    │  ② 头部：radiowaves + 主题
│  运行中 · 已播 7 首 · 待播 5 首           │     状态行（实时）
├─────────────────────────────────────────┤
│  ┌────┐  Sign of the Times              │  ③ 在播（ANCHOR）
│  │封面│  Harry Styles                   │     封面 + 曲名 + 歌手
│  └────┘  「承接前面那股孤独，先不急着亮」   │     + 主播按语（RadioTrack.why）
├─────────────────────────────────────────┤
│  接下来 · 主播排的 12 首（此处列前 5）      │  ④ 节目单（主角，只列前 5，点任一首=跳到那首）
│  ① Attention          「开头三十秒就有钩子」│     ①..5 曲名 — 歌手 + 一行按语
│  ② Counting Stars     「把心跳提一拍」      │     数据源 = radioPlaylist（现成）
│  ③ Die For You        「情绪回落，深潜一次」 │     完整队列在播放页的播放列表里，不在这里
│  ④ Photograph         「木吉他，换口气」    │
│  ⑤ exile              「大歌收束」         │
├─────────────────────────────────────────┤
│  ▸ 主播思路（最近一轮）                    │  ⑤ 折叠区（默认收起）
├─────────────────────────────────────────┤
│  ▸ 这一档听过的（台账）                     │  ⑥ 折叠区（默认收起）
├─────────────────────────────────────────┤
│         结束这一档                         │  ⑦ 吸底主操作（唯一终态）
│  音乐将暂停，队列保留；情境连续时           │     后果写清，不做系统弹窗
│  再次开启可续上这一档                       │
└─────────────────────────────────────────┘
```

| # | 区块 | 数据源 | 现状 |
|---|---|---|---|
| ② | 主题 / 状态 / 已播·待播 | `radioState` + `radioCardState.theme` + `radioPlaylist` | ✅ 现成 |
| ③ | 在播曲 + 按语 | `radioPlaylist[0]`（`title`/`artist`/`why`） | ✅ 现成 |
| ④ | 节目单（每首带按语，**只列前 5**，点任一首=跳到那首） | `radioPlaylist.drop(1).take(5)` | ✅ 现成（`RadioTrack` 带 `why`；跳转需按 id 解析回 `MusicInfo`）|
| ⑤ | 主播思路（最近一轮） | `radioCardState.lastAdjust` | ✅ 现成（**历史多轮需新增暴露**）|
| ⑥ | 台账（settled 事实） | `RadioSession.settled`（**私有**） | ❌ 需新增 `RadioArchiveState` 转发 |
| ⑦ | 结束这一档 | `MasterAgent.stopRadio()` | ✅ 现成 |

**v1 = ②③④⑦**（零后端改动，纯 UI）；**⑤多轮 / ⑥ 属 v2**（需新增状态转发）。

## 4. 手势分工（必须写死，否则打架）

内容区是滚动列表，面板又能下滑关闭 —— 两者必须明确分工：

| 手势 | 条件 | 结果 |
|---|---|---|
| 下滑 | **列表不在顶部** | 列表正常滚动（面板不动） |
| 下滑 | **列表已在顶部**且继续下拉 | 面板跟随位移；松手按**位移/速度阈值**判定收起或回弹 |
| 下滑（任意位置） | 从**头部/抓手条**区域起始 | 直接拖拽面板（不等列表到顶）|
| 上滑 | 任意 | 列表滚动（不关面板）|

实现走 **nested scroll 的 overscroll 判定**，不自己造阈值表；头部区域额外挂拖拽（`draggable`）——这是"全屏面板"的标准分工，避免"想滚却把面板拖没了"。

## 5. 收档语义：关闭不是断电

「结束这一档」必须把后果讲明白，且**它与 STRONG_CONFIRM 不是一类动作**：

| 维度 | 停止电台的实际行为 | 所以 |
|---|---|---|
| 音乐 | **暂停**（`stopRadioInternal` 一律 `pausePlayback = true`） | 有可见副作用 → 需门槛 |
| 播放队列 | **保留**（不清空播放列表） | 不破坏用户数据 |
| 会话档案 | 丢进 `retained`（**进程内**保留） | 情境连续时再开启可**续上这一档**（`tryResumeRetained`）|
| 用户数据 | 不动 | 不可逆性 = 无 |

→ 结论：**可逆动作**，按项目分级**不该走 STRONG_CONFIRM**；门槛由**面板本身**承担（长按进面板 + 看清 + 点按钮）。

**收档后的收束语**（面板转「已收档」态后展示，数据来自 `settled`，属 v2）：
> 这一档听了 4 首、切走 3 首，共 23 分钟。队列留着 —— 想接着听，再开一次电台。

***

## 6. 严格不做什么

- ❌ **不做对话输入** —— 面板 ≠ 第二个对话页（对话走对话页）
- ❌ **不做"换一批 / 换主题 / 调方向"** —— 那是新的 agent 能力，属另立阶段；本面板只是"看 + 收档"
- ❌ **不提供播放/暂停/切歌控制** —— 播放控制不归电台管（`agent-radio.md` 契约）。
  ⚠️ **例外（2026-09-19 追加）：允许「跳到某首」**。它不算"接管播放控制"：跳转是**用户对编排的表态**（不是电台替用户操作），且**必须在既有队列里定位**（`playWith` 先查重、找不到才追加）——**绝不新建队列**，否则会把主播刚排的队冲掉。
  观测后果（诚实说明）：跳转走 UI→控制器路径（项目惯例，"埋点下沉到控制器实现层"），因此电台**通过播放服务的结算事件**（`SKIPPED_NEXT`）看到这次跳转 → 计入台账、触发换批；但**「连跳感知重排」（`skipEvents`）不覆盖** —— 该缺口自"播放页切歌"起就存在，不是本次引入
- ❌ **不显示模型自由文案** —— 只渲染结构化字段（`why` / `reason` 本就是可枚举字段）
- ❌ **不主动出现** —— 纯用户唤出；不做"电台开启时自动弹一次"
- ❌ **不复用 STRONG_CONFIRM 弹窗**（§5 已论证）

## 7. 与既有契约的关系

**C1（静默 / 存在面）**：存在面从 2 处扩为 3 处，但**性质不同**，需在 `agent-radio.md` §3.3 登记：

| 存在面 | 出现方式 | 性质 |
|---|---|---|
| `RadioCard` | 常驻（不点进去看不到） | 状态面 |
| 伙伴胶囊电台态 | 电台开启期间常驻（图标 + 高亮，零文案） | 状态位 |
| **电台控制台** | **仅用户长按唤出** | **详情面（不主动出现 → 不算打扰）** |

**C3（会话边界）**：控制台成为"手动关闭"的**主入口**（另两个：对话说「停电台」/ Agent 看板停止按钮）。**停止仍是唯一终态**。

## 10. v1 实施记录与偏差（2026-09-19）

**与设计不一致的地方（刻意收敛，不是遗漏）**：

| 设计 | v1 实况 | 原因 |
|---|---|---|
| 头部显示「已播 N 首」 | ❌ 只显示「状态 · 待播 N 首」 | **播放计数未暴露**（`RadioSubAgent.playedCount` 私有）。**不编造数字** —— 要么不显示，要么另开转发字段（v2 一并） |
| **下滑关闭面板** | ❌ 未做。关闭 = 点缝隙（顶部 44dp 留缝）/ 收起按钮 / Esc（桌面） | 下滑关闭需与列表滚动做 nested scroll overscroll 判定（§4），属独立增量；v1 先把"看清 + 收档"落地 |
| ⑤/⑥ 折叠区 | ⑤ 主播思路直接展示（未折叠）；⑥ 台账未做 | `lastAdjust` 只一条，无需折叠；台账需 `RadioArchiveState`（v2）|
| 面板"就地转已收档态" | 改为**直接收起** | 电台消失 → `LaunchedEffect` 自动关面板；收束语要 `settled` 数据（v2）|

**已落地的设计要点**：① 面板是**只读观察窗**，打开期间不碰电台任何状态；② 遮罩点外关闭 + 面板吃掉内部点击（不穿透）；③ 收档走**滑动**而非单击；④ 后果文案常驻在滑块下方；⑤ 全部文案为中文硬编码（与 `RadioCard` / `AgentMonitorScreen` 同惯例 —— agent UI 本地化整体后置，**未新增资源键**）。

### 10.1 式样对齐 `MusicDetailDialog`（2026-09-19 追加，用户决议）

用户要求"弹窗的式样需要向音乐详情弹窗对齐"。核查发现项目弹窗有**统一基座**，于是控制台改为复用它，而不是自绘遮罩：

| 维度 | 原自绘 | 对齐后（= `MusicDetailDialog` 一套） |
|---|---|---|
| 容器基座 | 自绘 `Box` + 自建 scrim + 手写点外关闭 | **`ScrimDialog`**（`common/dialogs/base/`）——内部是真 `Dialog`：0.5 黑遮罩、居中、点遮罩关闭、**系统返回键天然可用**（顺带解决 D1 原列的"要自己接返回键"）|
| 圆角 | 24dp | **28dp** |
| 外边距 | 侧 12 / 底 12 / 顶 44 | **四周 24dp**（近似性保留："几乎占满"= `fillMaxSize` + 24dp 缝）|
| 材质 | 纯 `surface` | **`hazeEffect` + `hazeTintAlpha()` 容器色**（`hazeState != null` 时），elevation 0 |
| 标题 | `titleMedium` + Bold | **`headlineMedium`**、`onBackground` |
| 正文/行 | `onSurface` / `onSurfaceVariant` | **统一 `onBackground`**，层级靠字号（`titleMedium` / `labelMedium` / `labelSmall`）与 `primary` 强调 |
| 进出场 | 淡入 + 上滑 | **无动画**（与 `MusicDetailDialog` 一致：`if (!visible) return`）|
| 内层点击 | 自绘吃点击 | 保留（本面板含拖拽滑块，比参考弹窗更需要；参考弹窗点卡片空白会透传到遮罩）|

**刻意保留的两处偏离**（均为可用性，非式样）：
1. **保留「收起」按钮** —— 满屏面板下 24dp 外缝太薄，单靠点外关闭不好按；
2. 收档滑块用 `colorScheme.error`（语义色）而非 `Color.Red`（参考弹窗的收藏红）。

### 10.2 尺寸自适应（2026-09-19 追加）

**不做固定尺寸**：面板高度**随内容伸缩**（内容少就矮），仅当内容超过可用高度时才封顶并让中间列表滚动。

- 封顶值**实测可用空间**（`BoxWithConstraints` 的 `maxHeight - 48.dp`），不写死数字；
- 中间列表用 `weight(1f, fill = false)` —— `fill = false` 是关键：内容不多时只占自身高度（面板因此收缩），超高才吃满剩余空间并滚动；
- 宽度沿用项目弹窗惯例（24dp 边距内 `fillMaxWidth()`；`ScrimDialog` 各平台均 `usePlatformDefaultWidth = false`），**未加自定义限宽** —— 若桌面端显得过宽，加一条 `widthIn(max = …)` 即可。

### 10.3 未开启时是否屏蔽长按唤起？—— **需要，且已屏蔽**

**结论：屏蔽。** 未开启时长按**保持非电台语义**（现在是**直接进对话页**；原为轻量浮层，该层已于 2026-09-19 移除），不会唤起控制台。分流点在 `BottomFusionBar`：

```kotlin
if (radioActive) onOpenRadioConsole() else onCompanionLongPress()
```

三条理由：
1. **面板内容在未开启时不存在** —— 没有队列、没有编排、没有可收的档，打开只会是一个空壳（死界面）；
2. **未开启时长按已有既定语义**（现为"直达对话页"）。若被控制台夺走，就白丢一个主锚点入口；
3. **模式切换是显式的**：图标已随电台态从 `player_d` 换成 `radiowaves`，用户可以预期"长按的行为跟着图标变"。

补充：`radioActive = PLAYING / PAUSED / BUILDING`（与 `RadioCard` 同口径）——**"正在编排中"也算开启**，此时可打开面板（头部显示"正在编排…"，节目单可能暂空）。

### 10.4 节目单只列前 5 + 点击跳转曲目（2026-09-19 追加）

**用户决议**："控制台只显示待播的 5 条，要加入点击跳转曲目的功能。"

| 改动 | 实现 |
|---|---|
| 只列前 5 | 新增顶层 `private const val UPCOMING_PREVIEW = 5`；`preview = upcoming.take(5)`。**头部仍报真实总数**（`主播排的 N 首（此处列前 5）`）—— 诚实展示，避免"只看到 5 首却以为只有 5 首" |
| 点击跳转 | 每行 `.clickable { onPlayTrack(track.musicId) }`（**保留 ripple 作为可点的唯一视觉线索**，与只读文本区分）；**跳完不收起面板** —— 跳一首不代表"用完了控制台"，留着才能接着看编排、继续跳下一首；面板只读，开着不干扰播放 |

**分层**：`RadioConsole` 只抛 `onPlayTrack: (Long) -> Unit`，**不持有任何播放依赖**；解析与播放留在 `AppRoot`：

```
AppRoot: onPlayTrack = { id -> 收起面板; musicRepository.getMusicInfoByIds(listOf(id)) → playlistQueueViewModel.playWith(info) }
```

**为什么用 `playWith` 而不是新建队列**：`RadioTrack` 只有 `musicId/title/artist/why`（无 `MusicInfo`），需按 id 查回 `MusicInfo`（同 `HomeScreen` 先例）。
而 `MusicController.playWith` = `addToPlaylist`（**内部 `none{}` 查重，不会重复入队**）+ `playAt`（`switchToMusicInPlaylist` 定位 + 播）。
所以它**在既有队列里跳**，找不到索引时才会追加 —— 这正是"跳到队列里的某一首"，不会把主播刚排的队冲掉。

**为什么面板不列满**：面板是"看一眼这一档在播什么"，不是队列管理器。列满一屏会把它变成第二个队列页；5 首足以看出编排走向，完整队列仍在播放页。

**已知表现（不粉饰）**：面板不收起，所以跳转后"在播"那一行**可能要等电台下一轮判定才刷新** —— 镜像头（`radioPlaylist[0]`）是在换批执行时重建的，不是跟着播放器实时同步。跳转本身会触发一次结算 → 电台据此跑一轮 → 若判定为 replace 就重建镜像头（通常几秒内），判定为 none 则保持旧值。这是**既有镜像机制的表现**（`agent-radio.md` §7.1），非本次引入；若要即时，得让电台监听并镜像播放器的曲目变更。
