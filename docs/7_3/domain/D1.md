## 二、目标状态

做完之后，D1 应是：
- 三端「用户可见的播放能力」对齐：音效在三端要么都真实生效（FFmpeg avfilter / AVPlayer 均衡 / AudioEffectManager），要么都在 UI 上对 Desktop/iOS 明确禁用并标注「暂不支持」——杜绝「README 宣称支持、实际恒无效」的静默空桩（D1-03）。
- iOS 队列「下一首播放」与标签维度与 Android/Desktop 语义一致且都能持久化恢复（D1-01、D1-02、D1-07）。
- Desktop 退出与 seek 不丢数据、不误报错误（D1-04、D1-05），启动恢复失败可观测（D1-08）。
- iOS Live Activity 真正可构建、可显示，或 ROADMAP 状态修正为准确（D1-09）。
- 方向C（变速/Gapless/ReplayGain/交叉淡入）若启动，先在冻结接口补方法并同步三端适配器（D1-10）。

## 三、本轮发现

### D1-01　iOS「下一首播放」插入不持久化
- **现状（亲验）**：`MusicPlayerController.addToNextPlay` 修改 `currentPlaylist` 后**无** `persistCurrentPlaylistToDatabaseWithCurrentId()` 调用（`ios/HMP/HMP/Features/Player/MusicPlayerController.swift:225-232`）；同文件 `addToPlaylist`（L242-246）、`removeFromPlaylist`（L263-265）、`moveToTop`（L278-280）均有 `Task { persist... }`，唯独此处缺失。
- **影响**：iOS 上「下一首播放」插入在应用重启后丢失，队列恢复（来自 `loadPlaylistFromSettings`，L606-642）不含该插入。
- **动作**：在 `addToNextPlay` 内补 `Task { await persistCurrentPlaylistToDatabaseWithCurrentId() }`，保持与其他队列操作一致。
- **判据**：落不进 `:shared` 测试源集（iOS 分支本机/CI 均不编译，AGENTS.md §二、R12）。**待验**：iOS 实机，插入下一首 → 杀进程重启 → 验证队列含该曲；验完看「下一首」是否仍在队列正确位置。

### D1-02　iOS 智能歌单标签恒为空列表
- **现状（亲验）**：Kotlin 桥 `IosPlaybackController.getMusicLabels(musicId)` 是空实现，注释「iOS 侧引擎不提供，保持空列表」（`shared-ui/src/iosMain/kotlin/com/hearablemusic/player/ui/platform/IosPlaybackController.kt:123-125`）；`currentMusicLabels` StateFlow 在 iOS 永远是 `emptyList()`。
- **影响**：iOS 上 `currentMusicLabels`（PlaybackController.kt:50）恒空，心动模式（D1-07）与智能歌单展示拿不到标签维度，与 Android/Desktop 语义不一致。
- **动作**：从 Swift 侧 `loadMetadata`（MusicPlayerController.swift:348-368）注入标签，或在 `currentMusicLabels` 明确标注 iOS 不支持。
- **判据**：**待验**：iOS 实机播放带标签曲目 → 验证 `currentMusicLabels` 非空；或接 shared `getMusicLabels` 后经 `IosPlaybackStateSink.updatePlaylist` 同类机制推送。

### D1-03　Desktop/iOS 音效为恒无效空桩，但 AudioEffectsScreen 完整可点
- **现状（亲验）**：`AudioEffectsScreen` 提供均衡器预设/低音/环绕/混响/自定义均衡完整 UI（`shared-ui/.../ui/settings/pages/AudioEffectsScreen.kt:65-204`）；其后端在 Desktop 是 `/* TODO */` 全空桩（DesktopMusicController.kt:731-749，包括 `setEqualizerPreset`/`setBassBoost`/`setSurroundSound`/`setReverb`/`setCustomEqualizer`/`initializeAudioEffects` 全部空体，StateFlow 保持默认值 `bandCount=0`、`presets=[]`），iOS 同样全空实现（IosPlaybackController.kt:138-143）。README:34 宣称「支持均衡器、低音增强、环绕音」。
- **影响**：用户拖动音效滑块/选预设**无任何声音变化且无任何反馈**（`equalizerBandCount=0` 时自定义均衡器渲染 0 频段、预设列表为空），属于「UI 入口存在却恒无效」。
- **动作**：二选一——（a）方向C 落地 FFmpeg avfilter 真实实现（ROADMAP:488）；（b）在 Desktop/iOS 上对 `AudioEffectsScreen` 显式禁用或标注「暂不支持」，避免误导。
- **判据**：`initializeAudioEffects` 不抛异常 + StateFlow 保持默认值可在 `:shared-ui:testAndroidHostTest` 写断言（验证适配器不崩）；**真实音效生效落不进测试源集，待验**：macOS/Windows 实机选曲→调音效→验听声谱变化。

### D1-04　Desktop 退出时序竞争：异步落盘 vs exitApplication
- **现状（亲验）**：`Main.kt` 关闭/退出路径先 `musicController.release()` 再立即 `exitApplication()`（`desktop/app/src/desktopMain/kotlin/com/hmp/desktop/Main.kt:184-189`，标题栏 `onClose` L327-332、托盘 `onExit` L265-270 同构）；而 `DesktopMusicController.release()` 内 `persistCurrentPosition`/`persistCurrentPlaylistToDatabase` 均为 `scope.launch { ... }` 异步（`DesktopMusicController.kt:698-704`，实现见 L366-372、L500-511），`release()` 返回后 `exitApplication()` 可能在落盘前杀进程。
- **影响**：Desktop 正常退出时播放进度/队列可能未写入（settingsRepository / 播放列表表），下次启动恢复为空或旧值。
- **动作**：`release()` 改为同步等待落盘（如用 `runBlocking` 或 `scope` 改为等待 Job 完成）后再返回；或把 `persist*` 改为挂起函数并 `release()` 内 `runBlocking` 调用。
- **判据**：`:shared:desktopTest` 写测试：stub `AudioEngine`，调用 `release()` 后断言 `settingsRepository.currentPosition` / 播放列表表已更新（需 stub 真实 DB 或 fake）。

### D1-05　Desktop seek 把正常协程取消误报为播放错误
- **现状（亲验）**：`FFmpegAudioEngine.seekTo` 先 `playbackJob?.cancel()` 再 `startPlayback`（`desktop/core-player/.../FFmpegAudioEngine.kt:167-190`）；旧协程在 `audioStream.read` 抛异常，被 `startPlayback` 的 `catch (e: Exception)` 捕获（`L404-405`，`HmpLog.e`），且因 `isStopped==false`（seek 不置 `isStopped`，仅 `stop()` 置位）触发 `onError?.invoke(e)`（`L406-409`）→ `DesktopMusicController` 的 `audioEngine.onError` → `showToast("Playback error: ...")`（`DesktopMusicController.kt:150-152`）。
- **影响**：每次 seek（拖动进度条）都会弹「播放错误」toast 并记 ERROR 日志，属正常运行路径被误判为故障。
- **动作**：在 `catch` 中识别取消（`e is CancellationException` 或 `!isActive`）时跳过 `onError`；或在 seek 取消旧 job 前加标志位避免旧 job 上报。
- **判据**：`:shared:desktopTest` 写测试：stub 旧进程读取抛异常/被取消，触发 `seekTo` 后断言 `onError` 未触发（或 toast 未发）。

### D1-06　iOS restoreSavedState() 是空实现，恢复耦合在初始化链
- **现状（亲验）**：`MusicPlayerController.restoreSavedState()` 函数体为空，仅注释「等待 initializeDefaultPlaylists 完成后再恢复」（`ios/HMP/HMP/Features/Player/MusicPlayerController.swift:602-604`）；真正的队列/进度恢复在 `initializeDefaultPlaylists()` → `loadPlaylistFromSettings()`（L606-642）→ `restoreLastPosition()`（L644-661）。若初始化在 catch 分支失败（L592-597）仍置 `isInitializationComplete=true` 但跳过重载，则启动恢复静默失败。
- **影响**：iOS 启动恢复依赖初始化成功；初始化异常时队列/进度无声丢失，无可见提示。
- **动作**：将恢复解耦为独立可重试路径，初始化失败给出可见错误而非置成功。
- **判据**：**待验**：iOS 真机（或模拟器）首次/二次启动验证队列与进度恢复；制造初始化失败场景验看是否报错而非静默。

### D1-07　iOS 心动模式降级为随机洗牌，无标签权重
- **现状（亲验）**：`MusicPlayerController.playHeartMode` 仅 `list.shuffle()`（MusicPlayerController.swift:284-295）；Android/Desktop 用 shared `getSimilarSongsByWeightedLabels` 按标签权重生成（MusicController.kt:801-815、DesktopMusicController.kt:600-631）。
- **影响**：iOS 心动模式语义与另两端不同——不是「相似歌曲」而是随机顺序，结果质量不一致（D1-02 进一步使标签维度缺失）。
- **动作**：Swift 侧经桥调用 `currentPlaybackUseCase.getSimilarSongsByWeightedLabels` 复用 shared 算法。
- **判据**：**待验**：iOS 真机触发心动模式，对比另两端结果是否按标签权重；shared 层该 use case 已有逻辑，iOS 仅需接线。

### D1-08　三端启动恢复异常被空 catch 静默吞掉
- **现状（亲验）**：Android `loadPlaylistFromSettings`/`restoreLastPosition` catch 后注释「Ignore」（MusicController.kt:314-323、325-336）；Desktop 同位置 `catch (_: Exception) {}`（DesktopMusicController.kt:182-187、196-197）。队列持久化失败时两端都有 `HmpLog.w` 可见（DesktopMusicController.kt:506-508、MusicController.kt:881-883），但**启动恢复**失败无任何日志。
- **影响**：启动期 DB/DataStore 异常（系统歌单行缺失导致 FK 失败等）被吞，队列/进度/最近播放恢复失败无痕，用户感知为「播放胶囊闪一下消失」类问题无声发生。
- **动作**：至少补 `HmpLog.w` 记录启动恢复失败，并暴露可观测信号（与队列持久化失败同口径）。
- **判据**：Desktop 部分可在 `:shared:desktopTest` 写断言（stub 抛异常调 `loadPlaylistFromSettings`，验证有日志/信号）；Android 部分落 `:android:core-player` 的 test 源集（已有 `MusicControllerTest.kt`），但该模块 CI 不跑（AGENTS.md R12），判据**待验** Android 真机/本机。

### D1-09　iOS Live Activity 扩展未编入构建且默认关闭
- **现状（亲验）**：`project.yml` 仅单 target `HMP`（type: application，sources `path: HMP`，excludes 仅 `.DS_Store`），`HMPNowPlaying/` 目录（WidgetKit 扩展，含 `HMPNowPlaying.swift`/`HMPNowPlayingLiveActivity.swift`/`HMPNowPlayingBundle.swift`）未被收录为第二 extension target（`ios/HMP/project.yml:14-55`，grep `HMPNowPlaying|app-extension|targets` 在 targets 段无命中）；`HMPMediaSession.isLiveActivityEnabled` 默认 `UserDefaults.bool` = false（HMPMediaSession.swift:18-21），且 `NSSupportsLiveActivities: true` 已设（project.yml:42）但无扩展提供 UI。ROADMAP:381 标「✅ iOS锁屏控制与Live Activity」过度。
- **影响**：iOS 灵动岛/锁屏实时活动永不显示（锁屏本身依赖 `NowPlayingInfoManager`，可用；Live Activity 这部分空壳）。即便开启 `isLiveActivityEnabled`，缺扩展 target 也无法渲染。
- **动作**：将 `HMPNowPlaying` 作为 WidgetKit extension target 加入 `project.yml` 并由 XcodeGen 生成；或修正 ROADMAP 状态为「锁屏 ✅ / Live Activity 未做」。
- **判据**：**待验**：需 macOS + Xcode（`xcodegen` 生成 workspace）→ 真机查看灵动岛/锁屏实时活动；验完看 extension target 是否出现在 build scheme 且活动可渲染。

### D1-10　播放速度/Gapless/ReplayGain/交叉淡入跨三端未做且接口未预留
- **现状（亲验）**：冻结 `PlaybackController` 接口（PlaybackController.kt:21-137）不含任何 `setSpeed`/`gapless`/`replayGain`/`crossfade` 方法；三端引擎 grep `speed|gapless|setRate` 仅在歌词 `KaraokeTiming.kt:257-268`（音频速率参数，与播放引擎无关）命中，引擎层无变速实现；ROADMAP:389、487 将其列入方向C 未排期。
- **影响**：方向C 落地时无法平滑接入——需先扩展已冻结接口并同步三端适配器（违反「增补成员需同步两侧适配器」契约，接口文件头注释 PlaybackController.kt:13）。
- **动作**：方向C 启动时先在 `PlaybackController` 补方法，再分别实现三端；本轮回填不展开（属计划项）。
- **判据**：落不进测试源集。**待验/计划**：方向C 排期后由对应实现 + `:shared:desktopTest`/`:shared-ui:testAndroidHostTest` 断言驱动。

## 四、四项横查

**数据正确性**
- iOS 队列「下一首播放」不持久化（D1-01）、标签恒空（D1-02）属数据正确性缺陷。
- 三端启动恢复异常被吞（D1-08），恢复失败即数据无声丢失。
- Desktop 退出异步落盘竞争（D1-04）属退出路径数据正确性。
- 量级提示：grep `catch (_: Exception) {}` 在 D1 相关三端控制器均出现（Android MusicController.kt:320、335、599 等；Desktop DesktopMusicController.kt:186、197、229 等），属系统性「静默吞异常」模式，非单点。

**并发与生命周期**
- Desktop seek 旧播放协程取消 → 异常被当 ERROR + 弹 toast（D1-05），是协程取消语义误用。
- Desktop `release()` 异步落盘与 `exitApplication()` 竞争（D1-04）。
- iOS `restoreSavedState()` 空实现，恢复耦合初始化生命周期（D1-06）。
- StateFlow 桥接：iOS 经 `IosPlaybackStateSink` 由 Swift 主线程推送（IosPlaybackStateSink.kt:19 注释「所有方法须在主线程调用」），跨线程推送会丢状态——属桥接生命周期约束。

**可观测性**
- 队列持久化失败：Desktop/Android 有 `HmpLog.w`（可见，良好）；但启动恢复失败无日志（D1-08，缺口）。
- Desktop seek 误报 `HmpLog.e`（D1-05）污染错误日志，掩盖真实故障。
- iOS 初始化失败仅置 `isInitializationComplete=true`（D1-06），无失败信号。

**测试覆盖**
- iOS 分支本机/CI 均不编译（AGENTS.md §二、R12），D1-01/02/06/07/09 全**无自动化覆盖**，只能真机验。
- 共享 `PlaybackController` 三端适配器（MusicControllerPlaybackAdapter / DesktopMusicControllerPlaybackAdapter / IosPlaybackController）无专属单测。
- Desktop 侧有 `DesktopMusicControllerTest.kt`（desktop/core-player/src/desktopTest，15 个 `@Test`，grep 口径：`@Test` 命中 15 处 L42-146），覆盖队列/定时等；D1-04/05 的修复可落入 `:shared:desktopTest`。
- Android `MusicControllerTest.kt`（android/core-player/src/test）存在，但 CI 不跑（R12），恢复相关（D1-08 Android 部分）判据偏弱。
