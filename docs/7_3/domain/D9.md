## 2. 目标状态

做完之后 D9 应该是：

- **iOS 桥注册零缺口**：`AppDelegate` 启动时注册的每一个 Kotlin 侧桥（`MetadataParserBridge` / `ArtworkBridge` / `TagWriterBridge` / `PlaybackBridge` / `PlatformServicesBridge`）都有对应的 Swift 实现与 `.register(...)` 调用；新增 Kotlin 桥时编译期/启动期即有"漏注册即失败"的断言或日志告警。
- **iOS Live Activity 要么真做要么删干净**：`HMPNowPlaying` 扩展要么作为 `app-extension` target 进 `project.yml` 并完成 WidgetKit 能力/entitlement 接线，要么移除死源码并撤掉 `NSSupportsLiveActivities` 的误导声明。
- **三端壳层行为收敛**：Desktop 单实例重复启动可归一聚焦已开窗口（或文档明确"静默退出"为预期）；主题监听线程在窗口销毁时正确停止。
- **打包身份正确**：macOS DMG 版本号来自 `release.toml` 派生值，不再硬编码 `"1"`；Android `allowBackup` 与密钥备份范围由 D7 协同定性（本域只保证开关与备份目录清单显式、可控）。
- **deep-link 不再空壳**：`hearablemusicplayer://` 要么在 `MainActivity` 解析并路由，要么从 Manifest 移除。

## 3. 本轮发现

### D9-01 · iOS `HMPNowPlaying` Live Activity 扩展不在构建图（空壳）
- **现状（亲验）**：`ios/HMP/project.yml:14-55` 的 `targets:` 仅声明 `HMP`（type: application）；`ios/HMP/HMPNowPlaying/`（含 `HMPNowPlaying.swift` / `HMPNowPlayingLiveActivity.swift` / `AppIntent.swift` / `HMPNowPlayingBundle.swift` / `Info.plist`）是 `ios/HMP/` 下与 `HMP/` 同级的目录，未被任何 target 的 `sources` 包含。`project.yml:42`（`NSSupportsLiveActivities: true`）与 `HMP/Info.plist:30` 却同时声明支持 Live Activity。
- **影响**：自定义锁屏 / 灵动岛 Live Activity 渲染（WidgetKit 扩展职责）永远不会被编译进产物；`LiveActivityManager.swift`（主 target）可 `Activity<HMPLiveActivityAttributes>` 启动活动，但自定义 UI 缺失，且 `HMPNowPlaying/Info.plist` 的 `com.apple.widgetkit-extension` 完全失效。功能处于"声明支持却无实现"的空壳态。
- **动作**：二选一——(a) 在 `project.yml` 增加 `HMPNowPlaying` `app-extension` target（sources 指向该目录、`info.path: HMPNowPlaying/Info.plist`、依赖主 app 的 `sharedIos`、开启 WidgetKit capability/entitlement）；(b) 删除 `HMPNowPlaying/` 死源码并撤掉 `NSSupportsLiveActivities`，停止误导。
- **判据（待验）**：需 **macOS + Xcode + iOS 模拟器/实机** 验。验法：① `xcodebuild -list` 或 Xcode 的 TARGETS 列表确认是否含 `HMPNowPlaying.appex`；② 真机播放后在锁屏/灵动岛查看是否出现自定义 NowPlaying Live Activity。落不进 `:shared:desktopTest` / `:shared-ui:testAndroidHostTest` / `commonTest` 任一 Kotlin 测试源集。

### D9-02 · iOS 标签写入桥 `TagWriterBridge` 从未注册（静默失效）
- **现状（亲验）**：Kotlin 侧 `shared/src/iosMain/.../MusicTagEditor.ios.kt:8` 调用 `TagWriterBridge.registered`；该桥对象定义于同文件 `:25`，约定"Swift 侧通过 `register` 注册 AVAsset 实现"。全仓库 `ios/HMP/**/*.swift` 中 grep `TagWriterBridge|MusicTagEditor|TagWriter` **零命中**；`AppDelegate.swift:21-22` 仅注册 `MetadataParserBridge` 与 `ArtworkBridge`。
- **影响**：iOS 上 `MusicTagEditor.writeTags()` 永远走 `bridge == null` 分支，返回 `Result.failure(UnsupportedOperationException("Tag editing is not supported on this platform yet"))`（`MusicTagEditor.ios.kt:16-18`）。`EditMusicTagsScreen` 保存标签在 iOS 静默失败，用户无反馈。这是典型的"漏注册 = 功能静默失效"。
- **动作**：在 Swift 侧实现基于 `AVAsset` / `AVAssetExportSession` 的 `TagWriterBridge.Writer`，并在 `AppDelegate`（`didFinishLaunching`，紧跟 `:22` 之后）调用 `.register(writer:)`；或在该桥对象上加启动期 `requireregistered` 断言，防止再次漏挂。
- **判据（待验）**：需 **macOS + iOS 模拟器/实机** 验。验法：iOS 打开 `EditMusicTagsScreen` 修改任一字段保存，确认文件标签被改写、`writeTags()` 返回 `success`；无法用 Kotlin 测试源集覆盖（桥属 iOS Swift 侧）。可在 Kotlin 启动路径加 `check(TagWriterBridge.registered != null)` 作为可观测兜底（落 `:shared-ui` 启动，但仅在 iOS 运行期触发）。

### D9-03 · macOS DMG 版本号硬编码 `"1"`（打包身份失真）
- **现状（亲验）**：`desktop/app/build.gradle.kts:357` `dmgPackageVersion = "1"` 为字面量硬编码；同文件 `:332` `packageVersion = project.findProperty("hmp.versionName")?.toString() ?: "1.0.0"` 兜底 `"1.0.0"`。两者均未接 `release.toml` 派生链（AGENTS.md §一 规则 1 要求版本只改 `release.toml` 经 `syncVersion` 同步；但此处 `dmgPackageVersion` 不在同步覆盖点内）。
- **影响**：macOS DMG 安装包版本恒为 `1`，与真实版本（v7.2.2）脱节；自动更新/用户判断版本失据，`pkgutil`/`mdls` 显示版本恒 `1`。
- **动作**：`dmgPackageVersion` 改为 `project.findProperty("hmp.versionName")?.toString() ?: "1.0.0"`（与 `:332` 同源），删除 `"1"` 字面量；并确认 `sync-release.py` 是否需把 `dmgPackageVersion` 纳入派生点（否则仍会随 `release.toml` 失步）。
- **判据（待验）**：落不进测试源集。macOS 机器验：`./gradlew :desktop:app:packageDistributionForCurrentOS` 后 `mdls -name kMDItemVersion <产物.dmg>` 或 `pkgutil --pkg-info <pkgid>` 应显示 7.2.2 而非 1。

### D9-04 · Android `hearablemusicplayer://` deep-link 声明但无处理（空壳）
- **现状（亲验）**：`android/app/src/main/AndroidManifest.xml:40-46` 为 `MainActivity` 声明 `<action VIEW>` + `<data android:scheme="hearablemusicplayer">` intent-filter；但 `MainActivity.kt`（全文件 1-137 行）**无 `onNewIntent`、无 `intent.data` 读取**。全仓源码 grep `onNewIntent|getIntent()` 仅命中归档文档，无主源调用。
- **影响**：该 scheme 是空壳——外部或自身用 `hearablemusicplayer://` 唤起时 `MainActivity` 无差别启动首屏、参数被忽略，等于死声明；`docs/archive/7_x/7_1/README.md:114` 曾列"深链：hearablemusicplayer:// 打开对应页"为待办，至今未实现。
- **动作**：要么在 `onCreate`/`onNewIntent` 解析 `intent.data` 做路由（需配合 `Routes` 导航），要么从 Manifest 移除该 intent-filter 避免误导。
- **判据（待验）**：实机验——`adb shell am start -a android.intent.action.VIEW -d hearablemusicplayer://x` 后观察是否触发任何路由/页面跳转（当前预期：仅冷启动首屏，无响应）。可补 `:shared-ui:testAndroidHostTest` 断言"`MainActivity` 不存在 `onNewIntent` 重写"作为静态闸门，但功能正确性仍需实机。

### D9-05 · Android `allowBackup=true` + 备份含 datastore/数据库（密钥暴露壳层入口，交 D7）
- **现状（亲验）**：`AndroidManifest.xml:18` `android:allowBackup="true"`，`fullBackupContent=@xml/backup_rules` 且 `dataExtractionRules=@xml/data_extraction_rules`；`backup_rules.xml` 备份 `datastore/player_preferences.preferences_pb`、`music_database`、`backups/`。若 `SecureStorageHelper.android` 的 API Key 落在这几类被备份路径内，则 `adb backup` / 云端自动备份可导出密钥。
- **影响**：属 D7（密钥暴露，AGENTS.md §八 地雷 #11 同主题）的壳层入口；本域只确认"开关与备份目录清单"事实，是否真的携带密钥取决于 `SecureStorageHelper.android.kt` 的存储路径。
- **动作**：与 D7 协同定性——确认密钥文件是否在备份范围内；若是，移出备份目录或置 `allowBackup=false`。
- **判据（待验）**：需 Android 实机 + 静态核查 `SecureStorageHelper.android.kt` 落盘路径是否落在 `datastore/`/`database/`/`backups/` 之一；实机 `adb backup` 后解包确认是否含密钥文件。本域仅标注开关事实，定性交 D7。

### D9-06 · Desktop 系统主题监听线程泄漏（macOS + Windows，低严重度）
- **现状（亲验）**：`Main.kt:217` `watchMacOSTheme { isDark -> systemIsDark = isDark }` 的返回值（dispose 闭包，`Main.kt:387` `return { thread.interrupt() }`）**未被接收使用**；同文件 `:213` 的 `LaunchedEffect(Unit)` 也无 `onDispose`。Windows 路径 `Main.kt:223` `DwmHelper.watchSystemTheme { ... }`（`DwmHelper.kt:124` 返回 `() -> Unit` dispose）同样未释放。`watchMacOSTheme` / `watchSystemTheme` 内部线程均 `isDaemon = true`（`Main.kt:384` / `DwmHelper.kt:142`）。
- **影响**：窗口销毁后主题轮询线程（每 2s 跑 `defaults read` / 读注册表）继续存活并写已无 UI 的 `systemIsDark`；因是 daemon 线程，不阻塞 JVM 退出，故**不会卡退出**，但属无谓资源泄漏与代码异味。
- **动作**：`LaunchedEffect(Unit)` 加 `onDispose { <dispose>() }`，保留 `watchMacOSTheme` / `DwmHelper.watchSystemTheme` 返回的闭包并在销毁时调用 `interrupt()`。
- **判据（待验）**：`:shared:desktopTest` 无法覆盖（属 Compose 窗口生命周期）。macOS/Windows 机器验：启动后退出应用，`jstack <pid>` 或进程观察确认 `macos-theme-watcher` / DWM 监听线程随 JVM 退出而消失（daemon 本就如此，故实际影响低，判据以"代码显式释放 + 进程无残留非 daemon 线程"为准）。

### D9-07 · Desktop 单实例重复启动仅退出、不聚焦已开窗口（产品取舍）
- **现状（亲验）**：`Main.kt:91-94` `if (!SingleInstanceGuard.tryAcquire()) { ... return }`；`SingleInstanceGuard.tryAcquire()`（`SingleInstanceGuard.kt:28-43`）用 `~/.hmp/hmp.lock` 文件锁，重复实例拿不到锁即 `return` 退出，**不向已开实例发任何唤醒/置前信号**。
- **影响**：已运行时用户再次点击启动器/双击，第二个进程静默退出，已开窗口不会被带到前台（对比 mac `open` / Windows 已有实例归一前窗的常见预期）。属产品取舍，非硬性 bug。
- **动作**：可选增强——重复启动时经本地 socket / 文件锁信号唤醒前一实例 `toFront()`；或至少在用户文档明确"静默退出为预期行为"。
- **判据（待验）**：Windows/macOS 机器验：已运行实例时再启动一次，观察是否出现第二个窗口或原窗口被激活——当前预期应为"无新窗口、第二进程退出"。落不进 Kotlin 测试源集。
  - **2026-10-08 续**：锁语义本身已有本机单测 —— `desktop/app/src/desktopTest/.../SingleInstanceGuardTest.kt` 4 例（取锁 / 同持锁期二次获取被拒 / `release()` 后可重启 / 崩溃残留的锁文件不阻塞启动）。仍未验的是**产品取舍那半**：重复启动时不聚焦已开窗口，需要 Windows/macOS 实机观察，本条不因此转为已完成。

## 4. 四项横查

- **数据正确性**：D9 不涉及业务数据持久化，但壳层承载"版本号"这一元数据。D9-03 指出 macOS DMG 版本号硬编码失真，属元数据正确性缺陷；Android 备份目录清单（`backup_rules.xml`）本身正确，但密钥是否越界交 D7。其余三端入口未引入数据损坏路径。
- **并发与生命周期**：Android `MainActivity` 生命周期挂接合理（`onStart` 绑服务 `MainActivity.kt:52`、`onDestroy` 解绑+release `:57`），无 `onStop` 误解绑风险。Desktop 退出链 `onCloseRequest`（`Main.kt:184`）依次 `musicController.release()` → `SystemTrayManager.dispose()` → `SingleInstanceGuard.release()` → `exitApplication()`；除 D1-04 已报的 FFmpeg 异步落盘竞争外，本域补充：**壳层无其他非 daemon 阻塞异步**——`hmp-jna-prewarm`/`hmp-prewarm`/`macos-theme-watcher`/DWM 监听均为 daemon（`Main.kt:112,121` / `:384` / `DwmHelper.kt:142`），不阻塞退出；唯一瑕疵是 D9-06 的 daemon 主题线程泄漏（不致命）。iOS `AppDelegate` 桥注册在 `didFinishLaunching` 顺序正确（Kermit → 权限 → Koin → 两个解析桥 → 播放桥/服务桥的 `Task`），但 `TagWriterBridge` 漏挂（D9-02）属生命周期内的注册缺口。
- **可观测性**：D9-02 的根因是"漏注册无告警"——Kotlin 桥对象 `registered` 为 `null` 时仅返回失败，无启动期日志/断言。建议在 `MusicTagEditor` 或 AppDelegate 注册处加 `check(registered != null)` 式启动期断言，使漏挂从"静默失败"变为"启动即红"。Desktop 已有 `startup-<时间戳>.log`（`Main.kt:64-79`）文件日志兜底，可观测性较好。
- **测试覆盖**：D9 全部发现（iOS 桥注册、Live Activity 扩展、macOS 打包版本、Android deep-link、单实例、主题线程）**均落不进现有 Kotlin 测试源集**（`shared:desktopTest` / `shared-ui:testAndroidHostTest` / `commonTest` 都不编译 iOS Swift，也不打包 Desktop DMG）。意味着这些壳层/打包正确性当前**零自动闸门**，只能靠人工在 macOS/iOS/Windows 机器验。这是本域最大的测试盲区。

## 6. 刻意不做（带改判条件）

- **不重复立案 D1 已覆盖的 Desktop 退出异步竞争 / FFmpeg 运行时路径**：D1-04 已报 `musicController.release()` 与 FFmpeg 子进程杀停的竞态；本域仅补充"壳层无其他未等待异步"（见 §4 横查），不再展开。改判条件：若后续发现退出链上有**非 daemon** 的未等待异步（如托盘 `dispose` 内部有挂起 I/O 未 `join`），则另立案。
- **不替 D7 定性密钥暴露**：D9-05 仅标注 `allowBackup` 与备份目录清单事实，密钥是否真实越界由 D7 裁定。改判条件：若核查 `SecureStorageHelper.android.kt` 确认密钥落在被备份路径内，则本域维持"壳层开关事实"定位，不越界写 D7 的修复动作。
- **不评估 iOS 播放后台音频的引擎细节**：`UIBackgroundModes: audio` 已声明（壳层事实），AVAudioSession 分类/远程命令的实际后台存活属 D1 引擎范畴。改判条件：若发现 `AudioSessionManager` 未在进入后台时保持 session active（壳层应触发却未触发），则立案。
- **不重写 `HMPNowPlaying` 实现**：D9-01 只判定"扩展不在构建图 = 空壳"，是否补齐实现由功能优先级决定。改判条件：若产品确认 Live Activity 为 v7.3 承诺能力，则转为施工任务而非仅标注。
