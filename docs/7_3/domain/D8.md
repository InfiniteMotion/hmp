## 2. 目标状态

完成后 D8 应是：

- **导航零歧义**：每个 `Routes.*` NavKey 同时具备 `NavigationGraph` 的 `entry<>` 与 `HmpNavBackStack` 的 `subclass` 注册；新增路由由编译期/脚本断言强制双注册，不再依赖"人记得补"。
- **导航测试是真闸门**：`RoutesTest` 验证"路由 ↔ entry ↔ serializer"三者一一对应，而非对 `: NavKey` 做恒真断言。
- **设计 token 全量落地**：新增代码不得引入新硬编码色/字号/尺寸（白名单 = `ColorTokens` / `TypographyTokens` / `HMPDimens`），有静态门禁；现状散落值收敛进度可量化。
- **i18n 闭环**：所有用户可见文案走 `stringResource`；agent 侧文案（`Lang.kt` prompt 库）未知键有显式告警而非静默空串；语言覆盖率可查。
- **无障碍基线**：关键交互有 `contentDescription` / 语义角色；动态主题对比度 ≥ 3:1（已实现）；系统字体缩放（sp 已承接）经三端真机走查无溢出。

## 3. 本轮发现

### D8-01 · NavKey serializer 漏注册（两路由会保存/恢复即崩）
- **现状**：`Routes.kt` 共定义 **30** 个 NavKey（`Routes.kt:17-184`）。`HmpNavBackStack.kt:23-62` 的 `SerializersModule` 仅注册 **28** 个 `subclass`，缺 `Routes.AI.AgentConfig`（`Routes.kt:143`）与 `Routes.Settings.AgentMonitor`（`Routes.kt:132`）；但二者在 `NavigationGraph.kt` 都有 `entry<>`（`NavigationGraph.kt:113-115`、`NavigationGraph.kt:173-178`）。`HmpNavBackStack.kt:20-21` 注释自陈"漏注册无编译期报错，仅在该 key 参与保存/恢复时运行时报错"。
- **影响**：进程重建 / 配置变更（旋转、内存回收）时 nav3 用 `SavedStateConfiguration` 序列化 NavBackStack，遇到未注册 key 抛 `SerializationException`，进入这两个页面后遭遇生命周期事件即崩溃（"进页面才崩"，iOS 尤甚）。
- **动作**：在 `HmpNavBackStack.kt:52-60` 段补 `subclass(Routes.AI.AgentConfig.serializer())` 与 `subclass(Routes.Settings.AgentMonitor.serializer())`；并加断言防回归。
- **判据**：commonTest（落在 `:shared-ui:testAndroidHostTest`，覆盖 commonTest 源集）新增断言：以 `HMP_NAV_KEY_SERIALIZERS` 为 `serializersModule` 的 `Json` 能 `encodeToString(Routes.AI.AgentConfig("x"))` 与 `encodeToString(Routes.Settings.AgentMonitor)` 且不抛异常；并断言 **30** 个 NavKey 全部被注册（遍历式断言，新增即失败）。

### D8-02 · `RoutesTest` 是恒真闸门，不守卫注册完整性
- **现状**：`RoutesTest.kt:215-246` 的 `all route classes should extend NavKey` 对 22 个路由做 `assertTrue(route is NavKey)`；而 `Routes.kt` 每个声明都带 `: NavKey`，断言必然为真。它既不覆盖全部 30 个路由（列 22 漏 8），也不触及 `HmpNavBackStack` 的 serializer 注册与 `NavigationGraph` 的 `entry` 覆盖。
- **影响**：导航注册缺陷（如 D8-01）无任何测试拦截；测试"写了等于没写"。
- **动作**：将恒真断言替换为"路由 ↔ entry ↔ serializer 三者对应"的断言；补齐 30 个路由全量列举；或改为编译期/脚本静态校验。
- **判据**：同 D8-01，新增断言落在 `:shared-ui:testAndroidHostTest`（commonTest）；移除/改造 `RoutesTest.kt:215-246` 的恒真循环。

### D8-03 · 设计 token 非强制、采纳不全（散落硬编码）
- **现状**：集中 token 存在——`ColorTokens.kt:5-29`（亮/暗双色板 + 品牌色）、`HMPDimens.kt:69-93`（`spacing/corner/type/icon/component` 三档尺寸）、`TypographyTokens.kt`、`AnimationTokens.kt`。但采纳不全：grep 口径 `\d+(\.\d+)?\.(dp|sp)` 在 `shared-ui/src/commonMain/kotlin` 跨 **~130** 个文件命中硬编码尺寸字面量；而 `LocalHMPDimens` / `dimens.` / `HMPDimens` / `ColorTokens` / `TypographyTokens` 的引用仅出现在 **~37** 个文件；硬编码 `Color(0x…)` / `#…`（扣 token 文件自身）散落 **~15** 个文件（设计 doc §已知偏差 R49 同口径，量级一致）。`design.md` 判据①明令"新增代码不得引入新硬编码色或字号"，但无机械门禁。
- **影响**：尺寸/色值漂移、暗色与亮色难同步、改主题时漏改；与"一套 token 长相契约"目标背离。
- **动作**：收敛存量散落值优先级低；先加静态门禁（自定义 lint / ktlint 规则或 `./gradlew` 校验脚本）拦新增硬编码，再逐步收口。
- **判据**：无法纯单测。落 manual——`material`：`AuditLogViewModel` 之类的"进页面才崩"不适用此处；此处以 `./gradlew-lowmem compileAll` 查下游破坏 + 代码评审为主；门禁归横切线 X（静态闸门）。验收看：新增 PR 中无 `Color(0x…)` / 裸 `.dp` 字面量（白名单 token 文件与 `HMPDimens.kt` 定义处）。

### D8-04 · `Lang.kt.resolvePrompt` 未知键静默返回空串
- **现状**：`Lang.kt:529-553` 的 `resolvePrompt` 在 `L10N_PROMPTS[key]` 缺失时 `?: return ""`（`Lang.kt:551`），对未知/拼错的 prompt key 静默返回空串，无日志、无异常。
- **影响**：若某处 prompt key 拼写错误，Agent 系统提示词变空串，模型行为异常且无任何可观测信号（属 D6 运行时，但 i18n 契约归本域核查项）。
- **动作**：未知 key 改为 `HmpLog.w` 告警 + 回落中文，便于定位。
- **判据**：commonTest（`:shared-ui:testAndroidHostTest`，因 `shared` 的 commonTest 亦跑）新增断言 `resolvePrompt("__missing_key__", "global", "zh", emptyMap()) == ""` 固化当前行为，并加断言告警日志被触发（用 `HmpLog` 测试桩或 spy）。联动 D6。

### D8-05 · 导航图无"死屏"（正面结论，亲验）
- **现状**：30 个 NavKey 中 4 个主 Tab（`Main.Home` / `Gallery` / `List` / `User`，`Routes.kt:27-36`）由 `MainShell.kt:41-59` 的 `HorizontalPager` 承载（第 0–3 页），`Routes.Main.Tabs`（`Routes.kt:24`）的 `entry` 渲染 `MainShell`；其余 26 个 NavKey 均在 `NavigationGraph.kt:54-208` 逐一定义 `entry<>`（逐一核对 route 类型与 entry 对应，无遗漏、无指向未定义路由的 entry）。
- **影响**：不存在"定义了路由却无入口"的死屏；但"有 entry 却漏 serializer"的 D8-01 风险独立存在。
- **动作**：无（仅记录为已验项）。
- **判据**：建议加 commonTest 静态断言"每个非 Tab NavKey 在 `NavigationGraph` 有对应 `entry`"——但 `entryProvider` 为 `@Composable` 难直接单测；更合适落地为编译期/脚本静态比对（横切线 X 的静态闸门）。

### D8-06 · i18n 覆盖率无门禁：旧平行副本未清、泰语大段未译、无键集合断言（2026-09-30 补立）
- **现状**（三件，均亲验）：
  1. **两套资源并存**：`shared-ui/src/commonMain/composeResources/values*/strings.xml` 14 个 locale 各 **789** 键（口径：`<string name="` 计数）；而 `shared-ui/src/androidMain/res/values*/strings.xml` 这套**旧平行副本仍在**——默认与 `values-zh` **472** 键、其余 12 语言 **471** 键，且 `karaoke_lyrics` 只有 `values` / `values-zh` 有、**其余 12 语言缺**。
  2. **无键集合校验**：`scripts/` 内无任何 `strings.xml` 引用；`shared-ui/src` 下无读取资源 XML 键集合的测试（唯一的 `LangTest` 只测 LLM 词表，不读资源）。ROADMAP 承诺的"键集合一致 / 占位符逐条 / 未译率阈值"从未落地。
  3. **泰语大段未译**：`values-th` 789 键齐（键集合本身无漂移），但 **258/789 行与 `values/strings.xml` 同键同值**（口径：逐行 `Trim` 比对 `<string name=` 行），含整句未译，例：`refresh_interval_hours`、`smart_refresh_desc`。合理同形（`ok` / `cancel` / `app_name`）混在其中，故该数只是量级、不是"未译条数"。
- **影响**：① androidMain 旧副本不随 composeResources 的键集合演进，Android 端存在"新键只在 Compose 资源里、旧副本缺键"的分叉（本次已实测到 `karaoke_lyrics` 缺 12 语言）；② 删键或写坏 `%1$s` 占位符无任何机器反馈，线上表现为文案缺字或 `stringResource` 格式化失败；③ 泰语用户所见大段为英文。
- **动作**：① 先核实 androidMain 旧副本的消费者（是否有代码走 `R.string` 而非 composeResources），据此决定并轨或删除；② 在 `commonTest` 落"14 个 locale 键集合互相等于默认 + 占位符集合逐条一致"的断言；③ 未译率作为可观测指标输出（不设硬阈值，先让数字可见）。
- **判据**：`:shared-ui:testAndroidHostTest`（覆盖 commonTest 源集）——故意删掉 `values-de` 的一个键、或改坏一个 `%1$s`，测试必红。未译率不出断言，只登记量级。
- **备注**：本条由 `TODO.md` §六 归口时立案（旧台账 R13），与本节 §4「i18n 无键漂移」的实测部分不冲突——**键集合当前确实齐平**，本条补的是它未覆盖的两处（旧副本、无校验机制）与未译率；但"结构性保证"这个措辞过强，已在该处订正。

## 4. 四项横查

- **数据正确性**：导航 save/restore 的正确性完全依赖 `HmpNavBackStack` serializer 注册完整性（D8-01）；一旦漏注册，序列化期数据即损毁。i18n 键集合在 14 locale 间确实齐平（各 789 键），但**没有任何机制在保证它**——无脚本、无测试，靠人工维持；另有两套资源并存与泰语未译问题，见 **D8-06**。
- **并发与生命周期**：主题切换（播放中动态主题、暂停回落预置）在 `AppRoot.kt:191-195` + `ThemeViewModel` + `ThemeManager.generateDynamicColorScheme`（`ThemeManager.kt:41-77`）闭环；动态取色与三端一致性需 iOS 实机确认（§5）。导航栈跨配置变更的恢复路径即 D8-01 命中点。
- **可观测性**：导航注册无完整性告警；`Lang.kt` 静默空串无日志（D8-04）；设计 token 采纳无度量/门禁（D8-03）。整体"注册即信任"，缺陷无运行期信号。
- **测试覆盖**：`RoutesTest` 为恒真闸门（D8-02）；缺 serializer 注册覆盖、缺 `NavigationGraph` entry 覆盖、缺 token 采纳门禁、缺 i18n 键集合与占位符断言（D8-06）。横切结论：导航与 i18n 的"结构性不变量"当前靠人工，无自动闸门。

## 5. 验证缺口

- **iOS 实机 / 模拟器（macOS，本机编不了 iOS）**：动态主题取色与暗/亮切换在 iOS 运行期是否无崩溃、`Haze` 毛玻璃在 iOS 实际渲染（`design.md` D-1 已确认 iOS 走 Haze 非原生，但运行期未验）。谁验：拥有 macOS + Xcode 的开发者，在模拟器/真机启动 `AppRoot`，进入播放页触发动态背景与切主题，看无崩溃、玻璃层可见。
- **macOS 实机（Desktop）**：Desktop 无边框标题栏透明沉浸（`design.md §6.2`）、系统托盘播放控制、快捷键（Space/←/→/L/C/Esc，`design.md` D-7）、暗色毛玻璃对比度。谁验：macOS 本机 `./gradlew :desktop:app:run`，逐项手动走查。
- **Windows 实机**：毛玻璃 `Haze` 在 Windows（Desktop 通用，无平台特例）渲染、标题栏/托盘行为。谁验：Windows 本机跑 Desktop，看玻璃与托盘。
- **无障碍三端真机走查**：动态字体（系统 fontScale 已由 `sp` 自动承接，无需额外代码）在最大字号下无布局溢出；关键控件 `contentDescription` / 语义角色经 TalkBack（Android）、VoiceOver（iOS）、讲述人（Windows）走查。`contentDescription` 当前散在 ~50 文件（`MusicListItem.kt` 等），未做系统性语义树审计。

## 6. 刻意不做（带改判条件）

- **不为导航引入代码生成式双注册**：当前手写 `entry<>` + `subclass` 两处。改判条件：D8-01 类"漏注册导致线上崩溃"在 v7.3 内再发生一次，则改为编译期校验或脚本静态断言（见 D8-05 判据）。
- **不补 14 语种之外的语种**：当前 13 翻译语种 + 英文默认（各 789 键，口径 `find composeResources -name strings.xml` 计数）已覆盖 ROADMAP 承诺的**语种数量**；未要求更多语言。**注意**："覆盖承诺"仅指键集合齐平，不含翻译质量——泰语大段未译与 androidMain 旧副本见 **D8-06**。
- **不重写 agent prompt 多语言为 `stringResource`**：`Lang.kt` 的 `L10N_PROMPTS` 是 domain 层纯 Kotlin prompt 库（ZH/EN），与 UI 资源分属两套机制；仅修 D8-04 的静默空串，不搬移结构。
- **不强收敛设计 token 存量硬编码**：存量 `.dp`/`.sp`/hex 散落量巨大（D8-03），一次性收口成本高且无功能收益；先门禁拦新增，存量随需求渐进。
